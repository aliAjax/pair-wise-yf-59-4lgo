# 帆船赛现场控制和申诉处理

源提示词摘要：竞赛官维护组别、航线、起航时间和处罚记录，计时员提交到达数据，裁判处理抗议、重赛、弃权和成绩更正；冲突或重复处罚进入复核，操作保留时间线。

## 技术栈

React 19、TypeScript、Vite、Ant Design、Redux Toolkit、RTK Query、React Router、React Hook Form、Zod、i18next。

## 本地运行

```bash
npm install
npm run dev
```

开发端口：`62024`

## 可用流程

- 竞赛控制：起航倒计时、比赛状态切换（开始、结束、弃权）、船队和航线查看。
- 成绩管理：计时员提交到达数据，竞赛官记录基础处罚并发布正式成绩。
- 抗议处理：提交抗议、仲裁复核、裁决/改判/驳回与重新确认，同时更新事件时间线。
- 数据使用 localStorage 持久化，刷新页面后继续保留。

## 赛后变更记录（抗议裁决 / 成绩 / 发布共用）

所有赛后调整都落在 `ChangeRecord` 上，净用时由记录统一派生，不再直接累加：

- **每条抗议只有一条处罚记录**（按 `protestId` 唯一）；重复处理同一份抗议不会多扣。
- **改判按差额调整**原记录的当前有效处罚值，净用时即时重算。
- **处罚一变，已发布成绩立即作废**（发布记录标记 `voided`，成绩退回更正状态）。
- 新裁决或改判后 `confirmed=false`，**仲裁重新确认前禁止发布**。
- **比赛结束或弃权后不再受理变更**；弃权同时作废全部正式成绩，且禁止再发布。
- 角色门禁：仅仲裁可处理/确认抗议，仅竞赛官可记录基础处罚与发布成绩，
  计时员只能提交到达数据；越权操作在 thunk 层挡回并提示。
- 时间线完整保留改判差额、作废重算、重新确认、发布与弃权事件。
